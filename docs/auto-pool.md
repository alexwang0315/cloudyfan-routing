# 依體檢自動換池（#78，ADR 0035 第 6–9 點）

白話說明：排行榜仍負責把模型初步分成高／中／低池；當自家模型體檢（#77）顯示某個模型明顯比排行榜分群更好或更差時，才自動調整它所在的池。每次調整都產生一份新的評分快照，舊任務繼續用舊快照；操作員可以一鍵回復，也可以整個關掉自動換池。

程式位置：`src/cloudyfan_jev/scores/auto_pool.py`，測試：`tests/test_auto_pool.py`。另在 `snapshots.py` 放寬一處：只有快照明示 `pool_override.disabled_tiers` 的池可以發布為空池，其他情況照舊拒絕。

## 已做

- **方案 A 覆寫**：`plan_override()` 依體檢紀錄規劃新快照，快照多一個 `pool_override` 欄位，記錄排行榜原分群（`original_grouping`，連續覆寫時沿用最初那份）、覆寫後分群、每筆移動與理由、依據（體檢紀錄 id、分數、Wilson 信賴區間、完整任務成本、能力價格比區間）。`profile.external_score` 保持排行榜原值，`scores_combined: false`；體檢分數從不與排行榜分數相加或平均。
- **顯著性＋遲滯**：每次最多跨一階。升池要比上一階「所有」有體檢的模型都好：自己的區間下界減去對方最高的區間上界，差距大於 `hysteresis`；降池反之。題數少於 `min_graded`、過期（`max_checkup_age_days`）、內容雜湊不符的體檢紀錄一律不採用。
- **降智暫停**：同一 `configuration_id`（固定版本）最近兩次體檢的區間顯著下降（前次下界減本次上界大於 `hysteresis`）就暫停入池，不等換版。暫停會延續到之後的快照，直到操作員以 `unpause=[...]` 明示恢復，恢復時回到排行榜原分群。
- **空池停用並告警**：某池因暫停而沒有候選時，新快照中該池為空、列入 `disabled_tiers`，並產生 `tier_disabled` 告警（`fallback_to_other_tier: false`）。派送時 `select_profiles` 直接報錯，不默默改用其他池。
- **不繞過資格**：只移動已在原快照池內的設定；被排除、未核准、不在快照內的設定，體檢分數再高也不入池。原快照過期就拒絕覆寫。被移動的設定必須在 `model_bounds`（與 `BudgetedCore` 同一份費用上界）中有已確認上界，否則記為 `fee_bound_unconfirmed` 並不移動。QCS 准入照舊在任務綁定時對新快照執行（`prepare_qcs`、`ScoreCore` 未改）。
- **新舊題隔離**：快照檔不可變；新快照只改 `current` 指標，已綁定舊快照的任務與續跑不受影響。
- **換池紀錄**：`AutoPoolController` 在 `auto-pool-log.jsonl` 寫入 `auto_change`（前後快照 id、移動、依據、暫停、停用池、告警）、`rollback`、`auto_switch`、`suppressed`、`no_change`（有告警或被擋的移動時）。
- **回復**：`rollback()` 以上一份快照的分群發布一份新快照（快照庫只前進，不倒退指標），並記錄回復來源。再按一次回復會回到剛被回復掉的那份。
- **總開關**：`set_auto_switch(False, ...)` 後，`evaluate()` 不發布任何新快照（包含降智暫停），只把「本來會怎麼換」寫成 `suppressed` 紀錄；沒有設定檔時預設開啟（使用者選擇自動換池）。

## 已測（離線）

顯著才換（升池、降池）、與排行榜一致時不動、遲滯擋下（同樣差距把門檻降為 0 才換）、題數不足不採用、降智暫停與明示恢復、空池停用並告警且派送拒絕、一般發布仍拒絕空池、未核准／不在快照內的設定不入池、缺費用上界不移動、過期快照拒絕覆寫、竄改的體檢紀錄被忽略、舊快照不變、換池紀錄內容、回復、總開關關閉與重新開啟。體檢紀錄是測試用假紀錄。

- 門檻（`hysteresis`、`min_graded`、`max_checkup_age_days`）是起始設定，未經實測。

- 告警只寫在換池紀錄中，Monitor 顯示與一鍵回復按鈕屬 #80；真實體檢是付費試跑，屬 #81。
