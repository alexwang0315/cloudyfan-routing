# 契約經驗庫（#75，依 ADR 0036）

## 白話說明

同一種任務契約／類別的題目會反覆出現，模型也常犯同樣的錯。契約經驗庫把這些「反覆出現的錯誤與解法」和「各模型在這類題目的成績」累積下來，之後（#76）才能做成經驗卡附在題目後面，減少每題重新試錯的升級成本。

這張單**只做儲存與累積**，程式在 `src/cloudyfan_jev/experience.py`（`ExperienceStore`），沒有接進 `Core`、prompt 或任何路由模式。

本文的「客戶」一律指客戶端（ADR 0009）。

## 已做的規則

| 規則 | 做法 |
| --- | --- |
| 來源只收結構化公開資料（第 2、6 點） | 每題一筆觀察：`supports`／`contradicts` 只收 `error_fingerprint`、`check_code`、`advisor_advice` 三種，欄位只有 `kind`／`code`／`detail`，字串必須是不含空白的代碼；整筆先過 `routing._reject_private`，私有驗收、隱藏答案等欄位一律拒收。 |
| 3 題成立、反例下架（第 3 點） | 同一事實要 ≥ 3 題不同題目支持才回傳；任何一題反例就下架，之後再有支持也不恢復。同題重複記錄只算一次，內容不同則拒絕。 |
| 私有層（第 4 點） | 客戶端自己的題目累積的事實只給自己用；帶 `detail`（表名、欄位名等客戶專屬內容）的事實永遠只在私有層。 |
| 共用層（第 4、5 點） | 需 ≥ 3 題且 ≥ 3 個不同客戶端支持、無反例。達門檻時呼叫可注入的 `rewriter`（開源顧問改寫；輸入只有 `scope`／`kind`／`code`），再由程式檢查改寫文字不含來源題目的原文片段（12 字元片段比對）、識別名稱、客戶端或題目編號。沒過檢查的改寫不保存原文。每次讀取都會針對目前所有來源重新檢查。 |
| 題目原文不落地 | `record(..., sensitive={"prompt": ..., "identifiers": [...]})` 只用來做去識別檢查，存的是加鹽雜湊。 |
| 可追溯（第 7 點） | 每條事實有內部編號 `fact_id`；來源題目與客戶端編號留在觀察紀錄中，`facts_for()` 給其他客戶端的共用事實不帶來源。 |
| 預設參與、可退出（第 8 點） | 新客戶端預設「貢獻」「使用」都開，`set_client_settings()` 可分別關閉。建題時用 `freeze_settings()` 複製當下設定進該題。關閉貢獻後，該客戶端所有題目立即從共用支持中扣除，不足 3 個客戶端的共用事實下架；不貢獻的題目仍累積它自己的私有經驗。關閉使用只影響拿不拿得到共用層。 |
| 模型成績 | `model_stats(scope, client_id=None)` 依精確 `role`／`model_version`／`effort`／`provider` 統計派送次數、通過率、平均成本；`unverifiable` 另計，不算通過，也不進通過率分母。不給 `client_id` 時是貢獻中客戶端的共用成績。 |
| 版本與完整性 | 每次變更 `version` 加 1；`export()` 附 `sha256`；`load()`／`open()` 驗雜湊、schema，並重新驗證每筆觀察，不符就拒絕。`save()` 以暫存檔原子替換。 |
| 撤回與保存期限（第 7、9 點） | `withdraw_fact()` 下架事實（理由需是代碼）；`withdraw_task()` 移除來源題目並禁止再記錄。事實帶 `first_seen`／`last_supported`／`retain_until`（最後支持日 + 365 天）；`purge_expired(today)` 只清掉超過 365 天且不再支持任何有效事實的觀察。 |

## 已測

`tests/test_experience.py`（38 個測試，合成題序列，改寫器用假函式，不呼叫任何模型）：3 題才採用、反例下架、私有欄位與自由文字被擋、帶客戶專屬內容的事實不共用、改寫外洩被擋且不落地、跨客戶端門檻、退出貢獻後下架、使用設定依建題凍結、模型成績分組與 `unverifiable` 另計、版本號、存讀與竄改偵測、撤回、保存期限。

## 未做／未知

- 沒有接進題目或顧問（經驗卡組裝、≤ 2 KB 限制、「樣本不足」標示都屬 #76）。
- 真實開源顧問的改寫品質未測；目前只證明「改寫結果不合格會被擋」。
- 12 字元片段比對與識別名稱比對是起始設定，可能誤擋常見字詞（偏保守），也擋不了改寫後的同義轉述。
- 鹽值存在經驗庫內，雜湊只防直接看到原文，不防對識別名稱的字典猜測。
- 退出貢獻的扣除以「目前設定」為準，會扣掉它退出前的題目（依 ADR 第 8 點）；舊題本身的凍結設定不變。
- 經驗庫目前是單一 JSON 檔；多程序同時寫入沒有鎖。→ 後來改由 `ExperienceStore.update` 持檔案鎖寫入。
- 改寫可延後（2026-11-19）：改寫器回傳 `DEFERRED` 時事實記為 `pending`，由 `pending_rewrites()` 列出、`apply_rewrite()` 套用；批次流程見 `docs/advisor-experience-card.md`。
