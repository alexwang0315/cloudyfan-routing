## 操作與資料意義

受控 `assemble_monitor` 保留原有登入及入口。候選池頁可以選擇已保存版本、
canonical 類別與觀測模式，按原分組及主備位置展開設定、資格範圍、健康時間
與全部適用原因。未啟用、未登錄、缺額及證據無法確認分開說明。配額未知，
資格、健康與派送授權分開呈現。

任務的「呼叫與選池明細」增加原凍結版本與已保存選擇理由，將直接選模、
實際分類、同池可用性備援及公開驗收後的品質補救分開。現在健康不改寫歷史；
缺少原始紀錄就顯示未知。校準證據識別、分類協定指紋與真正校準版本各有
自己的含義，不能互相代替。成本估計、實際 API 費用、客戶扣款及費用上界
維持原有意義。

新增 `mrc-observation-v1` 僅出現在受保護的操作員回應，原 API 欄位與客戶端
權限保留。局部證據故障保留其他可信項目；整份觀測不可用時明示失敗。若保留
上次成功資料，會標示舊資料與原時間。桌機輪詢保留可用焦點與展開狀態，延遲
回應不能覆蓋新的查詢脈絡。

## 驗收與可查核證據

主要界面是使用者核定的真實 loopback HTTP 與桌機 Chrome：沿用真實
Core／BudgetedCore／TaskService／Store／HealthStore，僅模型上游、時間與故障
資料為隔離合成。驗收會比對實際 MockTransport／網路紀錄、原始證據指紋及
帳務意義，確認重複讀取、展開及輪詢不新增模型、來源或核帳請求。

完整交付以 [標準驗證工具](tooling.md) 的收據為準：

```sh
python3 scripts/acceptance.py status
```

該命令重新驗證 `runtime/tooling/current.json` 指向的封存檔、輸入及證據指紋。
本次使用原提交 Core `471c87197ba387db179ee1f102a3882075756012`、Python 3.13.13
與 SQLite 3.50.4，凍結後執行 Core 原 integration gate、全部 Monitor 測試及
離線封裝；未新增測試排除或修改歷史原件。執行結果及測試集合數量以原收據
記錄為準，不能以舊工作單的數字替代。

選定的初次 RED、修正前瀏覽器失敗、最終 HTTP／桌機紀錄與 worker quick
收據保留在 `runtime/issue24-evidence/`，並列入最後交付的指紋索引。完整原始
合成資料仍保存在工作區的 `.scratch/issue24-implementation/`。後續通過不改寫
較早失敗；獨立 Standards 與 Spec 初次審查及修正後複核亦分別保留。
