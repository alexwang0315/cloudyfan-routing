# 修正研究接入固定略過 Jev

2026-10-23。前輪只做離線實作、既有證據盤點與 MockTransport 測試，沒有新的付費 API、部署、推送或 Git 提交。本輪依使用者授權檢查並提交到本機 Git，仍不授權付費、部署或推送。RG-01、原始答案、帳本與所有舊凍結計畫不變。

## 原因與前一輪結論修正

S50 的研究接入 `ResearchProvisionalCore._economic()` 固定回傳 `action=direct`，理由為 `direct_upper_when_comparative_success_unknown`，並且拒絕非空的分類校準 variants。實際 50 題 CloudyFan 有 13 次條件選模：低／中 8 次全直送中，中／高 5 次全直送高。並沒有實際算出「13 次都不值得分類」。

因此前輪只測到開源先答、順序升級、候選排序及健康檢查的保守研究變體，沒有測到付費 Jev 二選一或完整的分類回本判斷。既有費用、正確率仍是那個變體的真實結果，但不能歸因於新 Jev 選擇器。

## 已修正的接入

- 新核心 `scores.selector_research.SelectorResearchCore`／`build_selector_research_core`，版本 `sequential-evidence-selectors-v1`；舊預設與研究版本保留。
- 實際 SQL 研究的新 adapter 已整理為可重建的 `scores.sql_selector_research.build_calibrated_sql_research_core`，版本 `sql-evidence-selectors-research-v1`；原始工作區 `artifacts/jev-selector-repair-20261023/selector_adapter.py` 保留不改。新套件不再動態載入外部研究程式或需要真實付費答案才能執行合成回歸。它真正替換舊的固定 `_economic`，不是只換報表名稱。
- 低／中、低答失敗後中／高、中答失敗後中／高，都綁定精確候選、前次設定、Jev 日期版、公開診斷／修正契約及校準來源。第二次分類使用第二次實際答案與最新公開診斷。
- 缺校準、成本機率不完整或節省區間跨過門檻：準備階段回報 `CalibrationRequired`，不把它寫成「不划算」，也不先付開源首答再發現無法選模。
- 單一可用候選與速度限制各有獨立理由，不冒充費用判斷。備援組合沒有適用校準時明確停止，不無聲沿用主配置的風險資料。
- 真正會用到的分類費及後續生成都進完整預留；CloudyFan 最多三次作答、兩次分類，兩個基準仍最多兩次作答。保存與重播沿用原 intent／response 契約。

## 回本判斷

比較同一條件母體下「直接使用適當候選」與「付分類費後選模」的完整剩餘成本，包含失敗、修正、後續升級／分類與實際 fallback。

| 有證據的結果 | 新接入行為 |
|---|---|
| 淨節省下界高於事前固定安全餘量，且流程速度符合限制 | 呼叫 Jev |
| 連淨節省上界都不超過安全餘量 | 零分類，記 `classification_proven_not_economic` |
| 上下界跨越門檻、缺費用／風險／來源資料 | 待校準，停止準備，不固定選高一池 |

分類器回傳的選項機率不是答對機率；不能拿其自報信心填入風險。模擬成本區間也不是供應商硬費用上界。

## 校準資料現況

盤點七類既有證據、重驗 130 個來源雜湊。適用現行精確條件契約的真實校準樣本為 **0**。最新十八個獨立模型校準流程全部首答結束、Jev 零次；舊二元探針與 A/B、alpha 的模型／前次狀態／提示契約不同。

本次補齊的是資料契約、三類條件模板、來源盤點、拒絕不適用資料的檢查及完整模擬校準資料。沒有把合成樣本冒充真實校準，沒有從正式 S50/F50 答案或隱藏判分挑規則。

觀測校準必須標示 `observed_calibration`、獨立校準分割、樣本數、精確設定與契約、效期和可核對的原始來源。程式能核對綁定與來源完整性，不能單靠操作者填寫的獨立性標籤證明資料確實獨立。這項來源審閱仍需保留。

`offline_fixture` 僅能經專用 MockTransport 執行，包含 mounted transport 及執行前重新檢查；SQL 的 live-preparation 入口拒絕 fixture。啟動旗標、JSON 或 Mock 通過都不授權付費。

## 真實比較的啟動條件

1. **先取得獨立校準資料**：開源失敗→低／中；低失敗→中／高；中失敗→中／高。資料須有實際 Jev 選擇／fallback、後續模型成果、公開驗收及完整費用／耗時，不能重送歷史付費請求補造紀錄。
2. **精確對照**：版本、強度、供應商、量化、能力卡、提示、診斷、生成上限、候選與前次設定都須一致。現有 SQL 主備清單共有 81 個可能的精確條件組合；這是契約清單，不是每個模型各測 50 題的准入要求。未取得適用資料的備援仍保持待驗證。
3. **凍結可用範圍**：只將有適用證據的配置明列為本輪可執行；其他候選保留待驗證，不假裝已可備援。不能使用正式題結果回調門檻，也不能把舊流程改名成新 50 題結果。
4. **成本與核帳可執行**：分開分類與生成／升級的預留；確認身份、完整 usage／收據及未知費用即停。估計值不冒充實付或硬上界。
5. **取得新付費範圍授權後才採集**：本次明確禁止付費。既有已結束的研究授權不因餘額尚有剩餘而自動展延。先完成校準，再凍結新比較題庫／排程與執行版本。

在第 1 項尚缺資料時，可以準備獨立校準作業，不能宣稱已達正式比較資格。本次沒有新的真實降本率，也不提升任何正式放行資格。

## 本機提交的重建範圍

選擇器及 SQL 接入一併保存必要的順序執行／無答案提示模組，以及備援核心的三個預設行為不變的擴充接點。SQL 的私有支援類只保留既有准入、排序、健康與核帳方法，不提供原固定略過的分類函式或舊建構入口。所有新 SQL 測試均使用 `example/` 模型、合成來源與真 SQLite；不需要原始正式題、付費答案或憑證。

審閱另補上 fixture 客戶端覆寫防護：只有標準 Client／httpx.Client 的 MockTransport 能使用合成校準，不能藉自訂 call 方法繞過檢查。原先31項驗證是歷史紀錄，本輪新增與擷取後的數量、提交子集及完整工作區差異另記於提交審閱證據，不混稱原始工作區全綠。
