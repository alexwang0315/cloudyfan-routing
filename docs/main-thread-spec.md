## Problem Statement

CloudyFan Monitor 第一版本機接入規格。日期：2026-10-22（Asia/Taipei）。本規格整合使用者已確認的 Q1～Q12 與整體接入方案；使用者已授權開始本機接入及驗收，這份文件的整理與工作單發布不重新開啟訪談，也不暫停已授權工作。

CloudyFan 需要讓操作員在同一個控制台看清楚各應用正在處理什麼、採用哪種路由模式、失敗後是否升級，以及模型作答、分類與失敗請求實際花了多少錢。操作員也需要更新 23 類候選資料，並知道哪些類別及模式已有主服務註冊的契約，避免把排行榜候選誤認為可以執行的模型。

目前已有獨立 Monitor 套件，提供運作、任務、帳本、候選池及客戶端頁面，並有真實 Core 搭配模擬上游的離線與瀏覽器證據。它尚不能因此被視為完成本次主線接入：原入口的重送可能接續工作、服務容量未涵蓋跨 worker 的單一名額、到期與忙碌可能誤記為工程中斷，主服務身分輪替、30 天存取、至少 365 天證據保存及來源部分更新的接線也需要本次驗收。

這些差距會讓網路重送意外產生新費用、不同客戶端超出共用容量、長任務阻塞整頁監控，或因結果到期而失去核帳與歷史統計。需要在保留既有資格、預算、原始證據及舊任務設定的前提下完成接入，並明確區分本機功能驗收與真實供應商資格、正式部署及降本成效。

## Solution

第一版以同步 TaskService 的任務入口 POST /v1/tasks 接入 Monitor，使用兩個獨立客戶端進行本機驗收。單一 CloudyFan 操作員管理全域及個別客戶端的模式、來源更新與模型池；客戶端只能操作自己的任務及查看自己的結果與統計。客戶端是持續存在的應用或服務身分，換憑證不換身分。

保留 CloudyFan MRC、全大模型優先、全便宜模型優先、全開源模型優先四模式，沿用已註冊 Core／BudgetedCore 的路由與預算規則。全服務跨 worker／程序同時最多執行一件模型任務；滿載的新任務立即回 429、不暗中排隊，查詢、監控及管理仍能回應。同一客戶端以相同任務識別與內容重送，只取得原狀態或既有結果；確定中斷後只有顯式 resume 可以接續。客戶端斷線時，伺服器正常就繼續已接受的任務，斷線不代表取消或零費用。

結果查看與接續權限自任務建立起算 30 天，到期顯示「已到期」並拒絕讀取結果與接續。原始請求及答案滿 30 天後只列入清理審查；帳務、操作紀錄、歷史統計與使用過的版本證據至少保存 365 天，未核帳或有效引用則延保，實際刪除仍須逐項批准。

控制台保留 23 類高／中／低／開源四欄候選池視圖，每欄主選一個、備援兩個位置，缺額及未知如實呈現；另列類別乘四模式的契約註冊狀態。來源由操作員手動取得，先看差異再發布候選，啟用執行版本是獨立操作。主要模型與評測來源及其必要 schema 成功時，個別端點失敗、逾時或未查可發布明示不完整的候選；主要來源失敗則保留舊版。

完成以受影響檢查、真實本機 HTTP 搭配模擬模型上游、桌機瀏覽器操作，以及獨立的一次有界真實來源 GET 查核為準。任一必要證據不足，就明列尚未完成的項目；不以文件完成、既有測試通過或畫面可開啟取代本次接入驗收。

## Implementation Decisions

- **整合邊界**：Monitor 是受控入口與公開狀態投影，沿用 TaskService、RegisteredContract、BudgetedCore 與 Core；不另寫選模、公開驗收或計費演算法。類別 runner 的任務身分與主服務內部任務身分須一致，必要的每任務組裝不能破壞既有凍結契約。
- **身分與權限**：主服務的客戶端身分與憑證生命周期是權限來源；憑證輪替不改 principal，撤銷憑證即失去存取權。第一版是單一操作員管理身分，不新增多管理員分權或宣稱已能辨別多位操作者。
- **同步任務契約**：第一版保留同步建立與執行流程，另提供狀態、結果及顯式接續。客戶端不得自行指定操作員設定、runner、驗收器、模型、供應商或憑證。管理投影不包含原始提示、答案、私人診斷或存取憑證。
- **固定任務綁定**：客戶端與任務識別共同決定任務命名空間；首次有效建立時固定內容指紋、類別、模式、模型池與契約。個別模式覆寫優先於全域預設，設定切換只影響未來任務；舊契約不可被覆寫或默默替代。
- **重送與接續**：相同身分、任務識別及內容的重送為只讀，適用完成、執行中及確定中斷三種情況，不取得新的派送名額。內容衝突拒絕；只有明示接續確定中斷的原任務才可能執行，且必須經原資格、凍結設定及帳務檢查。到期或退休不允許復活或重用原任務識別。
- **服務級容量**：同一本機服務的所有 worker 與程序共用一個模型任務名額，涵蓋新任務及明示接續；不能只使用程序內鎖。滿載的新任務立即拒絕且不建立隱藏佇列。相同任務的查詢或只讀重送不占新名額。
- **執行所有權與中斷**：名額反映伺服器接受後的實際執行生命週期，不依客戶端連線存活決定。客戶端斷線不取消工作或提早釋放名額；程序中斷後須由持久狀態及原始費用證據判定，不因重啟後記憶體清空而自動續跑或放寬未知費停止。
- **並行觀測**：任務執行不能持有會阻塞同任務狀態讀取的整段存取鎖；到期與清理維護的保護仍須成立。Monitor 不因逐筆查詢一件長任務而阻塞整份 snapshot，執行中、忙碌、已到期及工程中斷須保持不同語意。
- **四模式**：CloudyFan MRC、高池優先、便宜優先及開源優先直接選擇主服務註冊的對應契約。保留 CloudyFan 最多三次作答與兩次分類，以及其餘既有模式的原嘗試上限；顯示三個備援位置不增加派送次數。
- **30 天存取有效期**：任務首次有效建立時固定建立與到期時間，30 天內才可讀取結果及依原條件接續；恰到期即拒絕，重送、查詢與重啟不延長。到期顯示為到期，不能泛化成工程中斷，也不能覆寫先前已確認的歷史結果。
- **保存期限與起算**：原始請求及答案滿 30 天後可列清理審查，並非自動刪除。帳務、操作紀錄、歷史統計與使用過的版本證據至少保存 365 天；一般紀錄從建立時點起算，共用模型池或契約版本證據從最後一次任務使用起算。單純查詢或重送不重設期限。
- **延保與清理**：未知費、未完成核帳或有效任務引用所需證據延長保存。清理功能只準備精確目標、大小、風險、開啟狀態與可刪資格的預覽；實際刪除須逐項批准，不得刪除防重送、退休、共享帳務或仍有效的版本引用保護。
- **共享帳務**：同一付款帳戶使用含原歷史的完整 BudgetStore，不為不同客戶端或服務實例另建乾淨帳本以繞過阻擋。第一版沒有每客戶端美元額度；客戶端費用與使用量只依可歸屬證據分列，未歸屬帳戶支出獨立保留。
- **費用投影**：依共享帳本身分去重，區分已知、未知、預留與待核暫扣；用量回報與最終核帳不重複累加。未知費用停止同帳戶相關客戶端的新派送，控制台不自動核帳或解除。主機、電力與人工未計價時維持未知。
- **歷史統計**：結果到期仍保存已確認的公開結果計數、費用與流程證據。首答與最終公開驗收、未知及未完成、升級、分類次數與延遲分開呈現；不把公開通過率等同獨立隱藏正確率，不把缺少的耗時填零。客戶端活動依已認證請求時間，不推算 TCP 連線或客戶人數。
- **候選池視圖**：保留 23 類，每類高、中、低與開源四欄，每欄三個主備位置；缺額不從其他池或類別湊數。開源集合可與品質分組重疊，不是第四層能力，也不由名稱推定授權、零費用或本地可部署。
- **契約矩陣**：逐類別與四模式呈現主服務的確切契約註冊狀態及缺少原因，沒有合法組合就於模型派送前拒絕。矩陣代表註冊狀態，實際派送仍遵守資格、費用上界、隱私、剩餘預算及原授權；瀏覽器不能補入任意契約或模型。
- **來源三個動作**：來源 adapter 手動取得並準備候選差異，操作員確認後發布候選，執行模型池啟用是獨立的受控操作。頁面定期監控讀取不觸發來源刷新、模型探針或付費分類，不建立新定時來源工作。
- **來源範圍與上限**：來源 adapter 只使用固定 OpenRouter 模型清單、一般與搜尋評測，以及有上限的模型端點 GET。每輪最多三個主來源加十二個模型端點，包含失敗在內最多十五次實際嘗試；單次最多十五秒、整輪最多六十秒，不跟隨 redirect，不自動追加重試或越權端點。
- **部分來源政策**：主要來源及必要 schema 失敗時整輪失敗、保持舊版；主要來源成功後，個別模型端點的 HTTP、網路、逾時與解析失敗一致歸為部分更新，未查項目另列。保留其他成功資料，明示成功、失敗、未查數目及原因；缺少供應商、費率、速度或健康資料時保留未知，不挪用舊資料冒充本次成功。
- **來源證據**：保存來源 URL、取得時間、來源原有時間、內容雜湊及必要 schema 證據，成功與失敗嘗試均可追溯且不包含憑證。品質保留來源原生尺度，報價情境、端點延遲與完整流程成本及速度分開，資料新鮮度依既定來源政策判斷，不因重新取得就推定重新評測。
- **來源驗收與資格分開**：一次真實有界來源 GET 使用獨立且明確記錄的測試窗口，不自動發布或啟用；其成功只證明該次連線與 schema。候選發布或模擬契約不建立真實模型、供應商、能力或費用資格，也不解除主線未知費停止。
- **操作一致性**：管理設定以 revision 檢查拒絕衝突，保留變更審計。不同畫面維持相同的模式、版本、期限、模擬標示與帳務口徑；審計不含原始提示、答案或憑證。

## Testing Decisions

- **驗證行為的原則**：測試以客戶端與操作員可見的狀態、HTTP 回應、派送紀錄、費用及證據變化為準，不為內部函式排列或鎖的特定寫法建立鏡像測試。已同意的最高共同測試界面是真實本機 HTTP 入口；模型上游保留 MockTransport，無須重新確認測試界面。
- **沿用基礎**：既有 Monitor 測試已使用真實 Core、BudgetedCore 與 TaskService 搭配 WSGITransport／MockTransport，涵蓋四模式首個模型、模式覆寫、原任務重播、共享帳本去重、未知費停止、權限與候選更新。來源測試已有有界 GET、缺值、舊來源、身分歧義、redirect、大小及 refresh 互斥的先例。保留這些證據並新增本次行為，不用舊數字宣稱新驗收已通過。
- **隔離測試環境**：使用新的獨立 fixture 資料、虛構模型憑證與合成費用，不載入真實模型憑證、不更改主線原始帳本、收據或研究執行狀態。只允許測試專用 loopback 服務及 port，其餘模型網路拒絕；保留實際 MockTransport 呼叫紀錄與網路限制證據，不只輸出寫死的零呼叫欄位。
- **身分及權限**：由真實本機 HTTP 的兩個客戶端驗證任務與統計隔離、拒絕跨客戶端結果及管理入口、操作員修改全域與覆寫。換發憑證後舊憑證失效，新憑證仍可依原身分取得有效任務與歷史統計。
- **四模式與固定綁定**：確認四模式實際進入對應既有 Core 契約，類別、模式與版本在新任務固定。模式、覆寫、模型池切換及服務重啟後，舊任務仍使用原契約；缺原契約明確拒絕。23 類候選缺額與每類四模式契約狀態一致，缺契約時零模型派送。
- **單一容量與查詢**：使用可控制完成時點的模擬長任務，在未釋放上游完成訊號前，另一客戶端的新任務即取得 429 且零額外模型呼叫；第一件結束後第二件不會自行啟動。以不同 worker／程序重做，證明服務共用一件容量；同時完成狀態、snapshot 與管理操作，不能等長任務結束才回應。
- **重送與接續**：分別在完成、執行中及確定中斷時重送同一身分、任務識別及內容，確認只讀且派送數不變；改內容拒絕。只有顯式接續中斷任務才可推進，既有收據不重發，原期限、資格、次數與未知費限制維持。
- **斷線與程序中斷**：透過真實本機 socket 斷線證明伺服器正常時原任務繼續、執行名額保持占用，以原身分及任務識別重新查詢取得結果。另驗證服務程序中斷及重啟不自動接續，不能以 WSGITransport 或單一程序內測例代替這兩種情境。
- **30 天邊界**：以可控時鐘驗證到期前、恰到三十天及之後的結果讀取與接續，確認 410 及「已到期」呈現；重送、查詢與重啟不延長。到期不誤標工程中斷，不覆寫已確認統計或金額。
- **至少 365 天保存**：以可控時鐘及引用 fixture 驗證一般紀錄從建立起算、共用版本從最後一次任務使用起算，查詢與重送不重設期限；未核帳或有效引用時延保。驗證原文滿三十天只列清理審查，以及精確清理預覽；本輪不實際刪除資料。
- **帳戶與客戶端費用**：讓 A 產生未知費，確認同付款帳戶 B 也不能新派送；保留帳戶歷史與未歸屬支出，客戶端只依證據歸屬。核對分類、生成、失敗費、預留與暫扣，確保共享帳本及最終核帳不重複計費，未知金額不顯示零。
- **來源故障矩陣**：在主要來源及單模型端點分別注入 HTTP、網路、逾時、JSON／schema 故障；主要來源故障維持舊版，單端點故障可形成明示部分更新。驗證成功、失敗及未查數目與原因、包含失敗的十五次嘗試上限、十五秒單次與六十秒整輪上限、redirect 拒絕及憑證不進證據。
- **手動更新與狀態分離**：驗證監控輪詢不呼叫來源或模型，更新只準備候選差異，操作員確認才發布；發布不改執行版本。未註冊版本不可啟用，舊任務不隨新資料變更，部分候選不能自動取得資格。
- **真實來源查核**：在獨立記錄的測試窗口執行一次限定 metadata GET，最多三個主來源加十二個模型端點，失敗也計入上限；不發模型作答、分類或核帳請求，不自動發布或啟用。保存實際嘗試紀錄、來源時間、schema 結果及缺額；失敗或未執行時列明尚未取得這項證據。
- **瀏覽器操作**：實際檢視桌機上的四模式、23 類候選與契約矩陣、忙碌、到期、歷史統計、未歸屬費用及來源完整度；檢查管理確認、設定衝突、錯誤登入與清楚的模擬標示，留存操作結果與畫面，不把離線 DOM 測試當成實際操作。
- **受影響檢查**：執行 Monitor 的既有完整檢查與新增回歸；若變更核心共用介面或 orchestration，執行核心要求的相應檢查及 integration gate。保留不相關 dirty 工作與歷史失敗，分清既有問題、此次引入的失敗及尚未執行項目。
- **完成門檻**：只有受影響檢查、本機 HTTP／跨 worker／斷線證據、瀏覽器操作與本次真實來源 GET 及 schema 查核全部取得適用通過結果，才稱本次本機接入完成。任一必要項目缺少，保持未完成並交代具體原因與下一步；通過也不建立正式供應商資格或真實降本率。

## Out of Scope

- 手機端介面製作與測試：2026-10-22 使用者明確要求停止，從本次接入驗收範圍排除；不重做或擴充手機畫面。

- 新的付費模型作答、分類、模型健康探針、付費重試或核帳請求；本機模型流程一律使用模擬上游，真實來源步驟只准限定 GET。
- 解除主線未知費停止、變更真實模型或費用資格、重審 S01～S08、恢復已終止的低池專測、擴大既有付費研究或新增全大模型實驗組。
- 服務部署、正式 TLS／SSO、多管理員分權、跨主機監控、大量並行模型執行及來源定時刷新。
- Queue 或 OpenAI／Ollama 相容協定的正式接入、歷史研究格式自動匯入、未經 Monitor 入口之舊任務自動接管。
- 每客戶端美元額度、猜測歷史費用歸屬、把開源視為免費或把端點公開觀測視為任務品質與效能保證。
- 實際資料刪除、自動清理、刪除未核帳或有效引用證據、撤除防重送與退休保護。
- 原始碼推送、公開軟體發布或新授權條款；發布本規格工作單不等於允許發布程式碼或私人執行證據。
- 將模擬通過率、合成費用或本機操作結果用作真實正確率、正式上線或商業降本成效的主張。
