# 模型體檢（#77，ADR 0035 第 1–5 點）

白話說明：讓開源顧問定期替雲端模型「考試」，及早發現換代或供應商調整後的品質下降。能用程式判分的題目一律由程式判分；開源顧問只在程式無法判分時閱卷，而且要先證明自己分得出對錯。

程式位置：`src/cloudyfan_jev/scores/checkup.py`，測試：`tests/test_model_checkup.py`。

## 已做

- **出題（變體）**：`make_variant(base, generator, seed=...)` 以題庫原題（`sql_exam.cases()`）為底，出題器（可注入的函式，日後接開源顧問）只能選門檻 `k`（1–6）與資料種子；題型、語意與判分標準仍由 `sql_exam.definition()` 的 Python oracle 決定，所以變體一定能程式判分。出題器回傳越界或格式錯誤時，改用 `program_variant()` 的決定性變體，並記在 `variant_fallbacks`。
- **程式判分**：`grade_program()` 在現有凍結 SQLite 工作程序執行答案、比對預期列。
- **考官檢查**：`check_examiner()` 用固定對照答案與 mutant 答案檢查考官，對照全判對、mutant 全判錯才通過；沒有校準題一律不通過。`examiner_gate()` 在顧問版本不變時沿用上次結果，換版才重新檢查。未通過或版本不符時，開放題不評分（`grader: null`），只留程式判分。
- **不考自己人**：顧問家族與受測模型家族相同時，出題器與考官都不使用，只用程式變體與程式判分（`same_family_avoided: true`）。
- **觸發邏輯**：`checkup_triggers()` 依固定週期（呼叫端給 `interval_days`，ADR 初定每週）與模型清單快照比對（新增、移除、內容變動）回傳觸發原因。快照由呼叫端提供，本模組不連網。
- **結果紀錄**：`run_checkup()` 產出 `model-checkup-v1` 紀錄：每題的變體、判分者、結果與費用；分數、Wilson 95% 信賴區間；完整任務成本（含答錯的呼叫，有任何未知費用時總數為 `null`，另列 `known_cost_usd` 與 `unknown_cost_count`）；`record_id` 是內容雜湊。

## 已測（離線）

變體可程式判分、越界變體被拒、程式變體決定性、考官檢查通過／不通過／換版重檢／無校準題、同家族迴避、出題器失效改程式變體、週期與清單變動觸發、紀錄格式與信賴區間數值、未知費用處理、受測模型只看到公開題目。出題器、考官、受測模型全為測試用假函式。

## 不在本單／未知

- 不改動任何模型池；換池（能力價格比、遲滯、降智暫停）屬 #78。
- 沒有接上真實開源顧問或前沿模型；真實體檢是付費試跑，要另行授權（#81）。
- 免費 GET 取模型清單的實際抓取未實作，只做比對。
- 題庫目前只有 SQL；開放題（考官閱卷）目前只有資料結構與流程，還沒有正式題目。題數、週期、信賴區間門檻都是起始設定，尚未實測。
