# 四工作槽、四組 S50 研究接入（離線）

目的：讓不同題目的完整流程同時進行，減少逐筆等待；同一流程內仍依序選模、作答、驗收及核帳。這次新增託管 Jev 對照，總規模為 **50 題 × 四組 = 200 流程**。這是獨立研究接入，沒有啟動真實派送，也沒有改寫舊凍結研究。

## 流程與範圍

| 組別 | 流程 | 作答上限 | 自建 Jev 上限 |
| --- | --- | --- | --- |
| A CloudyFan | 開源首答 → 低／中選擇並作答 → 中／高選擇並作答 | 3 | 2 |
| B 便宜先答 | 低池首答 → 必要時高池 | 2 | 0 |
| C 開源先答 | 開源首答 → 必要時高池 | 2 | 0 |
| D 託管 Jev | `typesafe/jev-router` medium → 必要時以最新答案及公開診斷補答 | 2 次客戶端請求 | 0 |

A 的原凍結 QCS／分類回本政策保留；原資料缺少可比較校準時直接選模，實際自建分類為零。本次容量壓力測試額外涵蓋允許的兩次分類，不能說成已更動原研究政策。RG-01、SQL 契約、模型池、題意及隱藏答案不變，沒有全大模型獨立組。

D 使用 Chat Completions、`plugins:[{"id":"jev-router","cost_tier":"medium"}]` 與 `X-OpenRouter-Metadata: enabled`；不再套自建分類器，也不指定伺服器端推理強度。保存實際模型、供應商、usage、候選、advisor、推理程度、fallback 與選擇原因。medium 不是費用上限。包括名單可能被忽略，必須查實際選擇及 `list_fallback`；硬排除／供應商限制違反時拒絕繼續。尚未證實與本地四池完全相同，預先標為**託管服務整體比較**，不歸因為演算法單獨差異。兩次請求不代表服務內部只有兩次生成／advisor 呼叫。[官方文件](https://openrouter.ai/docs/guides/routing/routers/jev-router)

## 實作與安全接續

原研究程式與結果保留在工作區 `artifacts/routing-parallel-four-arm-offline-20261022/`。本機提交審查將可重現的程式／測試擷取至 [scripts/research_parallel](../scripts/research_parallel/README.md)，另立 v2 harness／plan；尚未替換舊付費入口。擷取只調整封裝路徑、獨立 Mock 的公開排程來源，並補強快取回應與帳本身分比對，原研究與凍結規則不改。

- `parallel_runner.py`：固定四個完整流程槽；保留 A/B/C 原相對排程，D 按題目 ordinal 輪流插入。每個槽內依賴步驟依序執行。新建 Core 的 factory 必須符合凍結配置摘要；目前提供注入介面，沒有自動接上真實 QCS 付費入口。
- `concurrent_ledger.py`：派送前先原子預留整個流程最壞費用，四槽合計不能超額；SQLite 交易不跨網路等待。每筆已知費用增量入帳，收據後到以差額替代一次。真正未知／證據竄改／孤立 intent 會保留預留並停止所有新派送；已在途回應仍保存、核帳。不能預留時等待現有槽釋放，不跳選較便宜題目。
- `core_bridge.py`：強制注入上游、完整費用驗證及派送前授權／帳戶閘門。intent 先於派送，原始 response 先於解析；已保存答案直接接續，沒有自動付費重試。無答案錯誤沿原契約重答，有答案才用最新答案與公開診斷修正；備援也消耗既有嘗試上限。
- `hosted_jev.py`：純請求／回應 adapter，沒有預設網路、憑證或重試。`estimated_cost` 不當實付；完整費用證據無法確認就維持未知，不額外加算已包含的 advisor 費。
- `historical_readonly.py`：驗證舊來源、題目、設定、契約及費用前綴後連結115個終態；示範匯入 S50-038/C 原付費回應兩次只占一次嘗試、零新派送，原費用保留。未重驗 SQL、未讀隱藏答案。這不表示該工程中斷已解決。

流程結果與每次公開驗收都有不可變摘要及帳本錨點。崩潰發生在答案保存、驗收或完成封存的不同位置時，只補未完成步驟；來源或設定不一致拒絕沿用。完成資料仍保留原費用與原 API 耗時，重播時間不作 API 延遲，零新增支出不當降本。

## 30分鐘的條件與限制

計時器採既有165次 API wire 耗時、115個終態的流程深度，循環外推到 A/B/C 各50題；D尚無本輪真實測量，固定以10／30／60／120秒及一／兩次請求做敏感度分析。這不是統計信賴區間，也不是成功率預測。

假設包括：兩個驗收槽、每次公開驗收0.5秒、序列帳戶索引閘門每次0.05秒；啟動採前輪唯讀整理實測191.37秒，獨立判分暫估300秒、報告30秒。後三項未知的真實服務表現，尤其核帳閘門與整批判分，尚未取得新的實測證據。

結論：四槽具備在部分服務速度下完成200流程的容量；**尚不能保證真實200流程全部答對並在30分鐘內完成**。需要量到託管 Jev 延遲／補答深度、供應商四槽限流、完整費用即時證據、帳戶索引閘門與獨立判分時間，才可評估真實時限；不縮短答案、降低驗收或增加嘗試來湊數。
