# 持續查核：局部故障、長任務與桌機輪詢（Issue 28）

目前候選與歷史任務沿用 `mrc-observation-v1`。操作員讀取可更新原 Monitor
衍生摘要；不執行或接續任務、不佔用派送名額，也不刷新來源、模型、核帳
或健康。不新增配額、資格、TTL、預算或恢復政策。

候選投影的 `status` 分為 `available`、`partial`、`unavailable`。單筆證據的
型態、精確設定、類別、時間、來源指紋、品質、完整成本區間或速度無法確認時，
該筆資格保持 `unverifiable`，不以空值搭配「三維證據已記錄」。其他可信列
保留。整份受控契約無法取得時，原候選清單仍可讀，新增觀測明示不可用，
`tiers/excluded` 為未知而非成功的空清單，成功判定時間也保持未知。

歷史候選健康各自驗證原命名快照；單筆損壞保留其他獨立可信健康資料，
該階段的選擇與經濟理由保持未知。先前可驗證階段、其他任務及原呼叫明細
繼續顯示。不用現在健康補造歷史，亦不重新執行來修復證據。

組裝時，注入的觀測來源必須是既有受控 observer，並綁定同一 Store、
TaskService 及註冊對照。一般客戶端不進入操作員投影；權限撤銷、scope、
客戶端間隔離與任務到期仍由原身分及存取契約執行。

桌機將任務 snapshot 與候選讀取的成功／失敗分開處理。候選失敗不阻止
任務列表更新；保留上次同脈絡資料時明示「舊資料」、本次失敗及原判定時點。
所選新版本尚未取得清單時，不借用上次版本的候選。回應必須符合目前登入、
查詢脈絡及請求世代；延遲舊回應不能覆蓋較新的健康或選擇。

候選與原排除明細依版本、類別、模式及原設定／位置保留展開狀態；任務明細
沿用原任務識別。輪詢後保留可用的鍵盤焦點；原項目消失時移至可見的查詢
控制。登出會清除工作階段資料及展開狀態。未知、部分失敗及不可用都有文字。

[整合 HTTP 驗收](../tests/test_resilient_observation.py) 使用真實 loopback
HTTP、Core／BudgetedCore／TaskService／Store／HealthStore；只有模型上游、
時間與故障使用隔離合成資料。涵蓋受控來源錯配、局部／整份證據損壞、
兩客戶端、scope 與撤銷、敏感標記、長任務尚未釋放即回應、原30天存取，
以及工程中斷／未知費停止後的唯讀查核。比對實際 transport 紀錄、原始檔案
指紋與帳務意義，允許原衍生摘要、到期狀態與時鐘記錄的既有更新。

[桌機驗收](../scripts/qa_resilience_desktop.cjs) 以同一完整備援候選 fixture，
啟動已安裝 Chrome，實際登入、選擇脈絡、鍵盤展開、多次週期輪詢、局部／
整份失敗、焦點消失、延遲舊回應及客戶端憑證拒絕。每次使用全新輸出目錄，
保留截圖、無敏感內容的 HTTP／上游紀錄、來源指紋與失敗收據。私有程序管道
可控制合成時間與故障，產品 HTTP 不提供這些控制。

```sh
CLOUDYFAN_CORE_ROOT=<prepared-core> node scripts/qa_resilience_desktop.cjs <new-private-output>
CLOUDYFAN_CORE_ROOT=<prepared-core> python3 scripts/check --quick
```

本機合成驗收不表示正式模型已合格、主線已部署或真實可用率／節費改善。
完整 Monitor／凍結 integration gate 與獨立 review 是最後整合完成門檻；
原始失敗紀錄保持原樣，不因後續綠燈重寫。
