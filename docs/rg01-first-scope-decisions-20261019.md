## 八題語義固定

- **S01**：包含 paid／void 所有訂單；NULL amount 不計；空／全 NULL 合計為 NULL。
- **S02**：paid、有效 ISO 日期 `2026-01-01 <= day < 2026-02-01`，NULL 日期排除，ID 升序。其他區間須另有固定契約，不自動解讀「本月」。
- **S03**：paid 按 customer 成群，包含 NULL 與非 NULL 無主引用；COUNT 包含 NULL amount；保留重複金額；NULL customer 最先。
- **S04**：列出每位已宣告客戶，沒有 paid 訂單為 0；NULL／無主引用不配給任何客戶；按有號 ID 升序。
- **S05**：列出不存在匹配 paid 訂單的已宣告客戶；NULL 外鍵不匹配客戶 0 或任何客戶。
- **S06**：按 paid customer 成群，包含 NULL／無主引用；amount 降序、NULL 最後，同額取最小 ID；全 NULL 群仍取最小 ID。
- **S07**：paid 按 customer 分群；day 升序且 NULL 最先，再按 ID；NULL amount 貢獻 0，累加到本列。允許語義等價 SQL，不要求逐字抄寫 reference。
- **S08**：UNION 去重；NULL 一次；空字串保留；BINARY 大小寫敏感比較／排序，不做 trim、大小寫折疊或 Unicode 正規化。

customer／order ID 在各自表內唯一且非 NULL，保留**完整有號 int64**，0／負值都是合法 ID。
customer 外鍵可為 NULL 或不存在的 int64；這與金額範圍是不同約束。
day 為公曆 0001～9999 年的有效 `YYYY-MM-DD` 日期或 NULL，沒有 timestamp／時區換算。
amount 只是整數度量；若用於金額，呼叫方須先固定單位與幣別，不由本規則猜測或換算。

## 數值及輸出邊界的推導

在八類參考計算中，每個合計／分群／prefix 最多取 1000 筆 amount，所以任何插入順序下：

`abs(partial_sum) <= sum(abs(amount)) <= 1000 * 10^9 = 10^12 < 2^63 - 1`。

這個充分界限同時容納正／負值，不依賴正負抵銷，也不限制查詢必須依某個安全插入順序。
它只保證**所定題意的參考計算數值域**，不保證任意錯誤 SQL 的乘法、ID 運算或 Cartesian join 不溢位。
原有輸出上限 100 列／32768 cell bytes 等 executor 約束保留；若預期結果超出上限，須在派送前明確拒絕或另訂拆分契約，不能偷偷 LIMIT、截斷或刪列。

先前最大 int64 的抵銷案例保留為歷史診斷，在新 amount 域外；**不得用新界限回頭把舊探測算成成功**。
已知 P01～P13 的公開反例都仍在新域內，必須全部補齊，不會因數值域決定而消失。
