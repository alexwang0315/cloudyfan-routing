## Delivered behavior

- [Supplier verifier](provider-bounds.md): independent authenticated ceiling
  contract + fresh supplier enforcement state + key status, bound to exact
  Client/HTTP transport/credential/model/profile/provider/endpoint/request policy.
  Key credit, token count and prices alone never authorize a paid request.
- Request leases are one-use. A final no-I/O check runs after client locking and
  durable intent, directly before POST; expired/changed qualification records an
  explicit unissued zero-fee event, without a false provider generation ID.
  Billing failures after dispatch retain unknown-charge stops and reservations.
- [Identity](identity.md): private operator-owned SQLite token registry, HMAC
  digests, explicit scopes and expiry, revocation, atomic rotation and account
  disable, durable clock floor, HTTPS policy and safe errors. HTTP/Ollama/Queue
  use the existing authenticator seam; TaskService rechecks account activity
  before reads and execution, including already accepted queued jobs.
- [Retention](retention.md): versioned TTL, durable expiry and permanent
  tombstones across restart/clock changes; expired/retired requests cannot read,
  resume or recreate the same task. Optional policy is an actual lifecycle
  integration, not just a stored configuration field.
- Operator maintenance previews exact file hashes/sizes/open-file state and queue
  copies. Apply requires exact-plan approval, a qualified workers-stopped fence,
  unchanged files/configuration, complete verified accounting and safe paths.
  Shared budget/auth/lifecycle/queue databases are protected. Billing IDs/costs/hashes
  survive; prompts/answers/workspaces and terminal queue request copies can be
  erased only after validation. Confirmed never-dispatched terminal queue tasks
  have a separate strict zero-fee absence-evidence path; orphan artifacts block it.
  Running, ambiguous or unknown-charge tasks stop.
- Core retirement markers prevent direct Core reuse after owned receipts are
  erased. Queue maintenance persistently pauses admission/dispatch and refuses
  active/interrupted workers. A crashed maintenance owner leaves the queue paused
  for operator review; it does not silently release or replay work.

## Composition

Use the explicit setup in [identity.md](identity.md) and [retention.md](retention.md).
In particular, pass `principal_active=identity_store.is_active`, keep the allowlist,
set a versioned RetentionPolicy, and protect `(identity_store.path,)` through
`retention_protected_paths`. Pass the same trusted BearerAuthenticator to HTTP,
Ollama and Queue rather than trusting principal fields in JSON. Do not expose a
synchronous bypass alongside a claimed bounded queue service.

For queued retained tasks, QueueScheduler installs queue snapshot/erase callbacks
and a maintenance fence. The queue database uses `PRAGMA secure_delete=ON` when
removing request content. This does not establish erasure from SQLite backups,
external logs, snapshots, SSD recovery or other application copies. The embedding
application must stop out-of-band writers to the owned storage roots.

## Review corrections made during implementation

1. A blocking key GET could age a previously valid supplier state past expiry.
   Recheck after GET and the final no-I/O lease guard close both that path and
   delay during budget locking/intent durability. Independent mock reproductions
   now produce zero POST and known zero fees, including after receipt sync.
2. Previously observed token expiry could revive after wall-clock rollback.
   Persisting the greatest observed clock prevents it across reopen; registry/
   clock errors deny authentication without exposing credentials.
3. Queue submit and retention preview could acquire lifecycle/SQLite locks in
   opposite orders. Submit now acquires the task lifecycle guard before queue
   SQLite. Per-task locks allow unrelated tasks to proceed independently. An
   adversarial concurrent probe confirmed preview completes without waiting for
   queue timeout; the expired duplicate submit returns 410 with no model POST.

## What remains pending

RG-04 still needs an actual supplier mechanism covering the complete fee of an
in-flight request, independently qualified statements/issuer keys/control-plane
probe and effective account configuration. OpenRouter's ordinary key endpoint
supplies none of that additional protocol; no production supplier positive path
was verified. Synthetic signed statements prove only adapter logic.

RG-05 still needs reviewed deployment identity/TLS/secret management, account and
role ownership, real retention duration/data scope/approval, complete storage/
backup/log coverage and a verified maintenance fence in that deployment.
OIDC/SSO, general tenant administration UI and automatic deletion scheduling are
not supplied by this local API-token integration. Expiry during a running call
cannot cancel or refund it; its receipts remain until verified maintenance.
Partial purge keeps tombstones and requires operator investigation.

All ten formal gate records remain pending. No production qualification or new
model quality/cost-saving claim follows from offline test success.
