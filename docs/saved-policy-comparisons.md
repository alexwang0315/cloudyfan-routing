# Saved original-policy comparisons — Issue42 candidate

The operator can explicitly create an immutable report through `POST /monitor/comparisons`, supplying only a registered policy version and 1–20 distinct `{client, run_id}` identities. The same operator/host/origin guard protects the catalog and report GET. Customer tokens cannot see the global reports. No browser-provided path, URL, receipt, code or answer is accepted.

A comparison ID is a separate `cmp-` namespace. Creation never calls TaskService execution, queue admission, a model/tool client, source refresh, Budget report/sync or billing reconciliation. The trusted host maps identities to original binding, identity, retention and contract authorities. A short-lived subprocess receives only explicit host paths and values; the pure Core comparator receives only the verified, bounded JSON decision DTO, with no paths, client, service, callback, prompt, answer or diagnostic prose.

The implemented loader re-applies the original Backup policy's initial choice over the full recorded original tier pool, checking saved gate predicates against their historical Health snapshot and original checkpoint. A verified single public-pass task also re-applies the original stop rule from original response hashes and the independently retained public outcome. Missing or unsupported later decisions stay partial/unknown. Other routing families, non-initial availability/quality/classification decisions and nontrivial saved capacity-window references are not claimed reproduced by this loader. It does not requalify the original admission or financial authority, and never substitutes current health, quota, price or candidate inputs. The pure comparator additionally has bounded sequential/QCS rules, including fail-closed missing QCS calibration; that public unit coverage is separate from this HTTP loader's supported scope.

Original actual paths, task state and authoritative original Budget fees remain separate from reproduced decisions. Pending fees remain null/unknown, not zero. Customer usage fees come only from already-written customer ledger records. After original raw access expires, the loader uses safe retained history and a retained account/event identity to identify the original financial authority; it never opens the job, manifest, checkpoint or call payload. A missing safe anchor leaves the amount unknown. Comparison output does not renew access, change tariffs/modes/expiry, sign observations or adopt a policy. There are no alternative model outcomes, win rates or real-saving claims.

Private report files contain the fixed scope/time/versions/implementation hashes, safe frozen decision inputs and data-use limits, safe result, worker exit/PID/timing evidence, and final request/input/report hash seal. Report GET validates these saved files and returns the saved result; it does not reread task evidence or recompute. The capture uses per-source generations and captured original predicates; it is not an atomic transaction across all original stores.

Declared per-creation limits are 20 tasks, 256 source captures/projections, 4 MiB total source bytes, 1 MiB per original file, 12 candidates, 9 decision points, 256 KiB public result, and 250 ms pure policy computation. The isolated loader/compute child has a 2-second CPU and 5-second wall limit, is killed/reaped on timeout, and denies socket/DNS creation. These are worker limits, not a whole HTTP/OS-I/O latency guarantee. Oversized or unavailable sources produce explicit unavailable/unknown results; overall source-budget exhaustion is incomplete. Source DB+WAL bytes count toward the source limits. Thus a larger original database may be ineligible for this bounded loader; it is not scanned without limit.

SQLite never opens a live original pathname after a separate pre-check. Main DB and optional WAL are captured through safe parent/leaf descriptors with NOFOLLOW/NONBLOCK, regular/nlink/size checks, and stable before/after identities for both. SQLite opens only private temporary copies using ordinary committed-WAL semantics, readonly/query-only/timeout0, a row materialization limit and VM-step bound. It never uses `immutable=1` to discard WAL or writes original SHM. Original task, retention and run locks are shared/nonblocking and never created, changed or held for execution. Advisory locks assume original cooperating writers; arbitrary privileged writers are outside that contract.

Current validation is targeted and offline only: real loopback main-service HTTP, original Store/identity/Core/Budget/scheduler and MockTransport, with nonloopback denied. Initial failed runs and test-setup mistakes are preserved separately. Headed desktop, original Core integration full, original Monitor full/build, final fixed-source review and independent acceptance remain pending until their actual receipts exist. No provider spend, push, deployment or evidence cleanup follows from this document.
