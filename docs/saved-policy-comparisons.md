The same operator/host/origin guard protects the catalog and report GET. Customer tokens cannot see the global reports. No browser-provided path, URL, receipt, code or answer is accepted.

The trusted host maps identities to original binding, identity, retention and contract authorities. A short-lived subprocess receives only explicit host paths and values; the pure Core comparator receives only the verified, bounded JSON decision DTO, with no paths, client, service, callback, prompt, answer or diagnostic prose.

The host loaders re-apply the original ordinary Core's four modes, frozen QCS direct/classified choices and both quality stages, and Backup initial/same-pool/two-stage quality continuations. They verify original generation/validation and classifier input/response bindings, including original parse failure, missing-distribution and tie fallbacks. A content-derived configuration ID for an ordinary profile is an identity reference, not qualification. Original tiny fees accept bounded scientific notation and are displayed as equivalent plain decimals; saved economic money comparisons use exact bounded Decimal equality, not a tolerance.

Backup availability exhaustion uses separate checkpoint, attempt and saved-selection cursors. A verified empty same-pool decision must first reproduce `advance_quality_stage`; only its actual input SHA can become the next quality point's optional proof. The original availability stop remains unchanged, the transition consumes no generation, and the final public stop carries no exhaustion proof. Missing proof cannot authorize this reproduction. Every family stops after the first missing, inconsistent or different choice; a later actual answer is never borrowed to continue an uncertain reproduced path. Original actual paths and costs remain visible independently.

These are decisions from frozen admitted profiles and recorded gates. The loader does not requalify upstream whole-pool admission or financial authority, and never substitutes current health, quota, price or candidates. The response-window adapter checks original adoption/dispatch/configuration/window identities, physical group scope and the complete related observation prefix up to the recorded revision. Dependency responses may come only from explicitly selected tasks of the same client whose original permission and raw access period remain valid.

In particular, recorded open revision1/2 does not heal an original Health exclusion, and unreferenced raw data is not reopened to invent a past clock. Explicit controlled-source imports use a separate obligations protocol and remain unsupported by this response-reference adapter. Current window acceptance is still targeted and its corruption/source-discovery controls are pending final integration; a positive case is not a completed gate.

Original actual paths, task state and authoritative original Budget fees remain separate from reproduced decisions. Pending fees remain null/unknown, not zero. There are no alternative model outcomes, win rates or real-saving claims.

Private report files contain the fixed scope/time/versions/implementation hashes, safe frozen decision inputs and data-use limits, safe result, worker exit/PID/timing evidence, and final request/input/report hash seal. Implementation identity covers all three family/window adapters, original Core policy/routing/Decisions/usage/reasoning and capacity protocol definitions, and host metadata validators, plus Python/SQLite versions. The capture uses one private generation per source DB within a fresh report and recorded original predicates; it is not an atomic transaction across all original stores or a cache shared across reports. Unqualified economic savings are not a public output; original policy reason codes are distinct from achieved model-cost savings.

Declared per-creation limits are 20 tasks, 256 source captures/projections, 4 MiB total source bytes, 1 MiB per original file, 12 candidates, 9 decision points, 256 KiB public result, and 250 ms pure policy computation. The isolated loader/compute child has a 2-second CPU and 5-second wall limit, is killed/reaped on timeout, and denies socket/DNS creation. These are worker limits, not a whole HTTP/OS-I/O latency guarantee. Oversized or unavailable sources produce explicit unavailable/unknown results; overall source-budget exhaustion is incomplete. Source DB+WAL bytes count toward the source limits. Thus a larger original database may be ineligible for this bounded loader; it is not scanned without limit.

Main DB and optional WAL are captured through safe parent/leaf descriptors with NOFOLLOW/NONBLOCK, regular/nlink/size checks, and stable before/after identities for both. A rollback journal before or after capture rejects the read rather than making an uncommitted main file appear committed. SQLite opens only private temporary copies using ordinary committed-WAL semantics, readonly/query-only/timeout0, incrementally bounded row materialization and a VM-step bound. It never uses `immutable=1` to discard WAL or writes original SHM. Original task, retention and run locks are shared/nonblocking and never created, changed or held for execution. Advisory locks assume original cooperating writers; arbitrary privileged writers are outside that contract.
