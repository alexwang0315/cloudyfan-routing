# 先作答，再視驗收結果進入下一層選模

2026-10-20 使用者確認的新路徑：

1. 開源模型先答。通過公開驗收就結束，不呼叫 Jev。
2. 沒通過或無法驗收時，由 Jev 在低／中二選一，選好後**實際作答並驗收**。
3. 第二次仍沒通過或無法驗收，才由 Jev 在中／高二選一，再作答並驗收。
4. 最多三次作答、兩次分類。最後仍沒通過就保留 failed／unverifiable，不繼續嘗試。

中／高選擇器取得第二次答案及其公開診斷，而非重看開源首答。第二次若選中分且通過，就不支付中／高分類費；第二次若選低分且失敗，也會進中／高。中／高仍保留兩個選項，允許中分根據診斷修正自己，沒有擅自改成強制高分。

這與舊版不同：舊版選中分後立即再分類中／高，兩次分類之間不作答，整個流程只有首答和唯一修正。新版 routing_version 為 hierarchical-sequential-v1，engine_version 為 0.2.0；舊凍結 manifest 不得套用新規則接續或重送。原始實驗、答案、成本與舊成績不修改。

## 驗收與實驗的界線

成本實驗的目標是：整批題目全部答對的條件下，完整成本最低。驗收與補答用來計入選錯模型造成的額外費用；分類、生成、失敗、重試、修正與中斷費用都保留。品質未達事前標準時只報支出差異，不稱等品質節省，也不以刪除失敗題或只加總成功請求取代完整流程比較。

CloudyFan與對照模式的最多作答次數不同，必須在計畫和報告逐組明列；差異屬完整流程比較，不能全部歸因為Jev分類器的單獨增益。舊兩次作答結果不能當成這個新版本的真實比較結果。

此路徑需要應用提供可用的驗收結果。一般問答不會因模型回覆流暢或 Jev 信心高就自動知道對錯。本輪未新增通用判錯能力，也未修改 SQL 驗收器／RG-01。

成本實驗可在明確區隔的評估環境使用獨立判定結果量測完成成本；隱藏標準答案與隱藏診斷仍不能送進 Jev、修正提示或模型。正式服務不能將沒有判定工具的回答假稱為已驗證正確。本次只有離線模擬測試，沒有新品質、實際降本或延遲結論。

## 完整費用與中斷續跑

CloudyFan 付費派送前的預留改為：

- max_turns ×（開源單次上界＋max(低, 中) 單次上界＋max(中, 高) 單次上界）。
- 加上兩次 Jev 分類上界。
- 加上三個作答階段的 max_turns × max_tool_calls × 允許工具最高上界。

其他固定大模型、便宜先答／開源先答後直接升高的模式維持最多兩次作答。預留是最壞可能費用，實際成本仍逐筆按發生的請求計入；提早通過不會把沒發生的分類／作答算成實付。

任何一筆費用未知、請求身份不符或工程錯誤仍停止派送，保留答案、原始收據與預留；不為湊足三次而繞過停止規則。已確認費用且符合既有契約的無答案429消耗當次作答機會，新 CloudyFan 按剩餘階段進選擇器。分類器本身失敗不自動重送。

每個分類階段與作答階段有獨立請求 ID。中斷後沿原設定續跑，先讀已保存的回答／收據，不重送已成功付費的請求。新版須使用新任務 ID／新凍結計畫，不直接修改執行中的舊計畫。
