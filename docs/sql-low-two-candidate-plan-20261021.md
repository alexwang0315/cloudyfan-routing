# 低池兩候選：身分、准入契約與50題研究計畫

2026-10-21。這份計畫只準備兩個低池模型的能力量測，不是新一輪路由降本比較。**US$1是研究支出目標，尚未授權模型POST；完整供應商費用上界仍未知。** RG-01、題庫、公開驗收、隱藏判分器、舊資格與實驗結果均保持原樣。

[凍結計畫JSON](../examples/sql-low-two-candidate-plan-v1.json)包含計畫ID、輸入ID、模型設定hash、SQL／執行器來源hash、Python／SQLite版本、50題順序、公開任務hash、准入契約及費用矩陣。其餘欄位或來源改變時驗證拒絕；不在原計畫中換模型、改題或放寬規則。日期／效期讀取JSON，不把文件日期當成永遠有效。

| 低池備一待驗 | `google/gemma-3-4b-it` | `parasail/bf16`／Parasail | bf16 | `none`／省略reasoning欄位 |

宣告身分從既有[SQL主備對照表](../examples/sql-backup-candidate-review-v1.json)提取，與原SQL低池提案核對；沒有讀模型答案來挑選。輸入僅保留metadata與原始來源hash，見[輸入快照](../examples/sql-low-two-candidate-input-v1.json)。舊低池提案仍在受控工作區，不隨本次輸入複製私人原始資料；來源hash是追溯資料，不是供應商簽章。

兩者都沒有可證明不變的日期版／權重修訂；`runtime_identity_verified`、不可變版本及provider量化實測均為false。未來只接受固定回應ID／provider及精確參數，任一不符即停止，不能把別名自動加入白名單。API可驗回報的身分，不能證明供應商未揭露的底層權重／量化。

本輪只選兩候選，不表示低池已有第三個合格備援。Qwen／GLM的原多alias契約、Lightning的provider-default及其餘7個不完整位置保留原狀；不沿用別的設定能力或備援校準。排行榜是分群參考，不是SQL正確率。

## 2. 單模型成績與整批路由品質分開

凍結JSON的`admission_contract`是**離線準入契約草案**，不會修改現行catalog、資格判分或路由准入。

| 層次 | 本計畫的要求 | 不可推論 |
|---|---|---|
| 單模型能力量測 | 保存固定50題的首答／最終結果、SQL操作別計數、全部費用、錯題及工程／未知；錯題仍是量測資料，不因非50/50便刪除候選紀錄 | 模型已可派送、已具備整流程能力或正式資格 |
| 舊嚴格SQL資格 | `grade_model.qualified`仍表示50題最後皆通過、費用已知；原判分邏輯不變 | 將它偷偷改名成較寬鬆資格，或要求所有便宜候選一定取得這個標記才能被研究 |
| 條件式候選提案 | 未來依實際SQL操作、獨立升級風險及完整成本／速度、資料／來源／費用條件提出有限範圍候選；個別錯題不等於全域回退 | 本輪已實作新的runtime准入adapter，或可直接把舊research flag搬入正式包 |

這次準備不新增「最低答對率」去挑結果，也不調整RG-01。條件式准入的實際接入及獨立整流程證據仍是後續工作；不能因這份契約便啟用模型池。

## 3. 費用缺證矩陣

`fee_gap_matrix`按兩個configuration SHA256列出 **2模型 × 8元件 × 7路徑＝112格**，每格都有保障用量、費率、證據引用欄位，目前均pending／null。

- 元件：input、output、reasoning、cache_read、cache_write、request、classification、failure。
- 路徑：成功、拒絕、失敗、取消、斷線、上游retry／child、變價／在途。
- 帳戶、適用期間、結算終局性與完整每次美元上界均未知。沒有reasoning欄位、沒有Jev呼叫，不表示可替供應商的同名或另列費目填零保證。
- 只有這兩個生成設定可達，Jev／工具／其他模型呼叫數為0；這不核定它們未來用於完整路由時的費用。實付已包含的費用不可重複相加。

一般報價不是保證；`:free`報價也不補完整零費率證據。本輪不聯絡供應商，不用一次成功請求宣稱失敗／取消／重試全免費。[完整保障缺口](first-pool-fee-gaps.md)繼續適用。

## 4. 凍結量測流程

採原`sql-model-exam-v1`／Q001→Q050，不新增或重審S01～S08。只固定執行環境與本次來源身分，不改SQL規則。使用既有`MultiCandidateQualificationRunner`的新考試命名空間，不轉換任何舊manifest。

1. 依固定候選順序各一次`Reply OK.`身分確認，最多2次。每次最多128輸出token。
2. 每題兩模型輪替先後，各首答一次；公開未通過時，只允許同模型補答一次。不升級、不自動重試、不付Jev分類費、不啟用供應商fallback、外掛或工具。
3. 作答／補答最多4096輸出token；公開上下文最多32768 UTF-8 bytes。修正只用自己的前答及公開診斷，不讀隱藏判分或另一候選答案。
4. **最多2次身分確認＋100次首答＋100次補答＝202個生成POST，分類0。** 先在兩次身分確認後（`max_new_requests=2`）暫停核帳、確認保存與續跑；這些是同一批50題的前綴，不另重發。
5. 未知費、身分不符、未解決intent、429／供應商失敗、工程中斷、過期或缺授權／費用上界時停止新派送。候選不替換、失敗不刪，不透明重跑不允許。
6. 只有capture完整封存後，才讀獨立隱藏考官作後置統計。報首答／最後通過、模型失敗／工程／未知、SQL操作別分布、全部已知API費及原始API／驗收耗時；未知延遲不補造。不宣稱Jev、備援或路由降本成效。
7. 中斷後保存原版本與原收據；僅同一manifest接續，不重送已付費或不明請求。此計畫尚未查核是否有可重用的同題同設定舊量測，因此不假設舊研究能減少202次預留；發現可重用證據時先另立明確連結方案，不直接重送。

## 5. US$1研究目標與情境費用

以原2026-10-21端點價格快照（USD／百萬token）試算：Llama輸入0.02／輸出0.04；Gemma輸入0.04／輸出0.05。**本輪沒有免費GET或即時查價，這不是新的報價。**

| 候選 | 50次首答＋最多50次補答＋1次身分確認的token費情境 |
|---|---:|
| Llama | US$0.040985600 |
| Gemma | US$0.069679360 |
| 合計 | **US$0.110664960** |

輸入假設：身分1024、首答8192、補答16384token；輸出依執行器上限：身分128、每次作答4096。輸入假設不是tokenizer／供應商強制上限，32768bytes也不是token上限；沒有假定cache優惠或其他元件免費。因此US$0.110664960不是完整費用上界、預測實付或保證一定能在US$1內完成。

US$1是這個新階段的提案，不接續舊研究額度；`spend_authorized=false`且`research_overrun_risk_accepted=false`。現行runner首筆前仍要求全批`101 × sum(兩設定已驗證完整單次上界)`預留、有效授權及已知帳務；不能把本表token情境或US$1填成EnforcedBound。

若缺供應商保障而要走接受單筆超額風險的研究例外，須另外明確授權及審閱獨立版本的執行設計。**這份計畫沒有實作或啟用例外，也不放寬現有上界驗證器。**

## 7. 離線產生與驗證

必須使用鎖定環境的Python。系統Python可能帶不同SQLite／原生限制，會改變SQL公開契約與suite hash；不能為了套用舊hash而忽略這個差異。

```sh
.venv/bin/python scripts/prepare_sql_low_trial.py \
  --input examples/sql-low-two-candidate-input-v1.json \
  --verify examples/sql-low-two-candidate-plan-v1.json \
  --now <有效期間內的UTC時間>

# 新輸出只能寫到既有runtime目錄內的新檔，不覆寫
.venv/bin/python scripts/prepare_sql_low_trial.py \
  --input examples/sql-low-two-candidate-input-v1.json \
  --output runtime/low-two-plan-NEW.json \
  --now <有效期間內的UTC時間>
```

CLI沒有真實HTTP派送、憑證搜尋、查帳或自動啟用功能。過期plan可保留作歷史；新派送前的時效驗證會拒絕，不能改created_at冒充重驗。
