# 模型資格考試：保存答案、公開補答與中斷續跑

`QualificationRunner` 將既有 Client、共享 BudgetStore、固定版本表、SQL題庫及判分器接起來。
這是模型能否入池的考試，不是 CloudyFan 路由成效比較，也不恢復全大模型獨立對照組。
RG-01、題庫、六類操作與50題全部最後通過的門檻不變。

## 執行順序與隔離

- 固定四個設定：開源、低、中、高；先各做一次身分確認，再 Q001→Q050 依題號輪替四角色先後。
- 每題最多兩次同模型作答，沒有 Jev 分類、升級、工具、外掛、串流或自動網路重試。
- 只用該題公開契約與公開診斷修正；公開通過就停止，不看保留案例決定補答。
- API provider.only、allow_fallbacks=false、require_parameters=true、日期版及強度固定；身分不符即停止。
- `capture` 不讀隱藏答案或做隱藏判分。完整保存四個模型的50題後，才允許明確呼叫 `grade`。
- `grade` 沿用既有判分器。合成結果保持 synthetic；不自動核定候選、不切換 current、不改正式 registry。

## 費用與續跑

派送前預留完整404次呼叫的最大暴露：每設定一次身分確認＋50次首答＋最多50次補答。
這是保守全批預留，不把價目表估價當成可強制上界。呼叫者必須提供既有共享授權帳本、
各模型完整元件上界與實際驗證器；本模組不建立真實支出授權，也不豁免費用保障。
供應商 verifier 的 dispatch／POST 即時驗證介面可沿用；缺上界、授權過期或餘額不足時零POST拒絕。

每次派送先建立帳務事件，再由Client保存intent，回應先落盤才解析／驗收。
中斷後刷新原事件，不新增一筆歷史費用；讀回原答案與公開驗收checkpoint，不重送。
若事件已建立而intent尚未保存，或intent沒有response，保持未知停止，交由人工處理，不猜測請求未送出。

- API已含的費用只計一次；明確核帳後的 generation total 取代 response usage.cost。
- 不自動做供應商 GET 核帳；可在取得授權後明確使用既有Client.reconcile，再以同一exam ID接續。
- 未知費用、缺generation ID、重複ID、身分不符、429或其他HTTP失敗都停止整批；已知失敗費仍計入。
- 身分確認的四筆費用另外列入整批帳，不藏在50題判分小計之外。
- response usage費用保留未終局的上界差額；帳務預留釋放不代表供應商結算終局性已取得資格。
- 認得的空字串答案可按公開診斷補答；非文字／null／模型要求工具等不在本純文字捕捉契約內，保留費用並停止。

答案封存綁定原始intent／response與公開驗收checkpoint，不把後來核帳的衍生欄位混入答案身分。明確核帳後，capture（可用零新請求額度）或grade會先刷新同一帳務事件，再追加獨立billing版本；不覆寫原封存與先前紀錄、不重送答案。inspect只讀最後匯入帳本的視圖，不會自行連網核帳。

manifest綁定版本表、設定、suite與公開契約、執行器及grader來源、預算路徑、上界與驗證器描述。
修改輸入、模型或規則必須新exam ID與明示新計畫，不能改凍結任務續跑。
`max_new_requests` 只在固定順序的下一個新請求前暫停，不挑題、不抹去已付費結果。

此CLI只建立MockTransport、人工費率上界、合成授權及控制答案的模擬上游；不讀環境金鑰、不連網。
它演練完整50題×4設定、公開失敗補答、答案保存後驗收中斷、續跑及完成後零POST重播，

真實應用只能由已授權呼叫者注入Client與既有共享BudgetStore；沒有真實執行CLI或預設真實金鑰。

## 已知的接入修正與限制

原captured_attempt用評分層的compact JSON計算Client intent雜湊，真實Client使用另一個固定JSON編碼。
本輪改為沿用Client實際編碼，保留原response／intent，不改SQL判分與門檻。
舊合成fixture同步改用實際Client編碼；原失敗與成功接入紀錄分別保留。完整模擬另揭露補答診斷的JSON欄位順序造成接續payload不同，已改固定排序；同模型不同供應商／強度也改用明確角色綁定。完成後核帳不再改壞原答案封存，另追加帳務版本。

2026-10-29 使用者決定（選項A）：題庫身分 `suite_id` 綁定實際執行環境（平台、核心、Python 建置、SQLite 建置與 native limits）維持不變，
`examples/` 中凍結的 `8a3127cd…` 只在凍結的 Mac 上能啟動，其他機器照樣拒絕。測試改為：執行器機制測試使用以目前環境 `suite_id`
產生的測試用版本表複本；凍結檔另以「只把機器欄位換回凍結值後重算必須相等」檢查，雲端也能抓到題目或程式漂移；
另有測試在模擬的外部核心版本上確認凍結版本表被拒絕。低價兩候選 plan 只在凍結環境逐位元比對，其他環境比對除執行環境綁定欄位以外的內容。
凍結機器欄位見 `tests/sql_frozen_runtime.py`。這不改變任何正式資格或真實考試的規則。

模擬費用、模型身分及控制答案不證明真實模型能力或供應商上界。
真實API資格、來源使用與責任審閱、RG-04及其餘適用正式資格仍待核定。
